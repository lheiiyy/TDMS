## What S-09 must prove, and what each result decides

- **Transfers cleanly** (ownership accepted, script ID, sheet ID and folder ID unchanged, Script Properties present, deployment and URL alive): D069 stands and the runbook becomes verified.
- **IDs change, or the project or folder cannot be transferred:** the runbook section 4 (copy and re-point) becomes the main path, a new slice is needed for a Drive file ID remap tool (the `files` table stores Drive file IDs, ARCHITECTURE §9), and gate G-01 (a company Workspace account) is reopened for Leo.
- **The web app URL changes:** users must be told the new URL at a real move. **Triggers do not move:** recreate them. **Script Properties are lost:** Leo keeps the offline list (already the rule).
- **Not rehearsed:** the mail sender (CFG-007, no mail code exists), the Claude connectors (G-09), a Google Workspace target, the whole mother-folder transfer.

## If something goes wrong (rollback)

- **Ownership did not come back:** the second account opens **Share** and transfers ownership again. Ownership only moves when the receiving account accepts.
- **The web app is broken:** create a new deployment (steps 32 to 37) and archive the broken one.
- **Script Properties are missing:** enter `ENV`, `DB_ID` and `DRIVE_ROOT_ID` again from the offline list.
- **A sheet is damaged or lost:** copy the `S09-BACKUP-…` copy back into `TDMS-test`. The test sheet only holds `_meta`.
- **Nothing works:** delete and recreate the test project and sheet from the repository (`clasp`) and the backup. The IDs then change, so update `.clasp.test.json` and the Script Properties. The test environment holds no real data, so this costs time only. `dev` and `live` are never involved.
