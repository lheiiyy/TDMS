## Reading a refusal

A spike function that refuses returns `{"ok":false,"code":"SPIKE_DISABLED","reason":"..."}`. Only the fixed reason codes below are ever returned; the real error text is never shown or logged, because it can contain an ID.

| `reason` | Meaning | What to check |
| --- | --- | --- |
| `NO_DB_ID` | The `DB_ID` Script Property is missing or the properties could not be read | Project Settings, Script Properties: `DB_ID` exists on this project |
| `SHEET_UNREADABLE` | The database spreadsheet could not be opened. `error_kind` tells the kind | See the next three rows |
| `SHEET_UNREADABLE` + `PERMISSION` | The text mentioned permission, authorization or scope | Run a spike function once from the editor and allow the scopes. After a manifest change, deploy a **new version** of the web app |
| `SHEET_UNREADABLE` + `NOT_FOUND` | The text mentioned "not found" or "no item" | `DB_ID` is wrong, or the account has no access to that spreadsheet |
| `SHEET_UNREADABLE` + `OTHER` | Anything else | Report it to Claude with the other fields |
| `META_TAB_MISSING` | The spreadsheet has no tab named exactly `_meta` | The tab name, spelling and case |
| `MARKER_MISSING` | The `_meta` tab has no `environment` row, or its value is empty | Cell A2 is `environment` and B2 holds the value |
| `MARKER_NOT_TEST` | The `environment` value is not `test` | The value in B2 (it must be `test` on this project) |
